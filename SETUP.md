# Подключение базы и админки

Сайт работает и без базы: каталог берётся из `data/products.json`, а форма заявки
пишет в консоль браузера. Чтобы продавец сам менял цены и наличие и получал заявки,
нужен проект Supabase. Настройка занимает около 10 минут.

## 1. Проект

1. [supabase.com](https://supabase.com) → **New project**.
2. Название `maslov`, регион **Central EU (Frankfurt)** — ближайший к России.
3. Пароль базы сгенерировать и сохранить в менеджер паролей. Для сайта он не нужен.

## 2. Таблицы

**SQL Editor → New query** → вставить весь файл `supabase/schema.sql` → **Run**.
Должно появиться `Success. No rows returned`. В **Table Editor** появятся
таблицы `products` (13 товаров), `requests` и `admins`.

Скрипт можно запускать повторно: товары, которые продавец уже поменял, он не затрёт.

## 3. Ключи для сайта

**Project Settings → Data API** → скопировать **Project URL**.
**Project Settings → API Keys** → скопировать **Publishable key** (`sb_publishable_…`).

Оба значения вписать в `config.js`. Publishable key публичный — его и так видно
в браузере. **Secret key (`sb_secret_…`) и service_role никуда не вставлять.**

## 4. Учётная запись продавца

1. **Authentication → Users → Add user → Create new user**.
   Почта и пароль продавца, галочка **Auto Confirm User**.
2. Сделать его админом — в **SQL Editor**:

   ```sql
   insert into public.admins (user_id, email)
   select id, email from auth.users where email = 'почта-продавца@example.com';
   ```

3. **Authentication → Sign In / Providers → Email** — выключить
   **Allow new users to sign up**. Иначе любой сможет зарегистрироваться через API.
   Прав у такого пользователя не будет, но лишние учётки в базе ни к чему.

## 5. Проверка

- `admin.html` → войти → поменять цену у любого товара → обновить главную: цена новая.
- Поставить товару статус «Нет» → на сайте он пропал. «Под заказ» — появилась пометка.
- Оставить заявку на сайте → вкладка «Заявки» → **Обновить**: заявка с номером `МС-26-0001`.

## Как устроена защита

- Права проверяет **база**, а не страница админки: политики RLS в `schema.sql`.
  Админ — это не «вошёл», а «есть в таблице `admins`».
- Посетитель не видит таблицу заявок вообще. Заявку он создаёт только через
  функцию `submit_request()`, которая возвращает лишь номер.
- Позиции и сумму заявки база пересчитывает сама по id товаров: цену из браузера
  можно подменить, поэтому ей не доверяем.
- Не больше 5 заявок с одного номера за 10 минут — простая защита от спама.

## Известные упрощения

- Нет уведомлений о новой заявке в Telegram — продавец видит заявки в админке.
  Подключается Edge Function по той же схеме, что в проекте fasady-yana.
- Каталог рендерится в браузере: Google его индексирует, Яндекс — хуже.
